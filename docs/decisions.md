## 2026-11-10 · `ignore-scripts=true`
У lock-файлі немає пакетів з install-скриптами; заборона закриває клас атак через `postinstall`. Браузери Playwright ставляться явною командою (`npx playwright install`), не скриптом. Побічний ефект: npm не виконує й власні `pre*`/`post*`-скрипти `package.json` — їх не використовуємо. Після кожної нової залежності — перевірити `hasInstallScript` у lock-файлі.

## 2026-11-11 · Маршрутизація мов і 404 (Task 3, після рев'ю)
**Заміри.**
1. `notFound()`, викликаний зі сторінки, у Next 16.1.7 / 16.2.12 / 16.4.5 / 16.4.6 віддає сервером порожній документ `<html id="__next_error__">` (без `lang`, макета й тексту); 404 малює лише клієнт. Відкритий баг vercel/next.js#62228 (з 2024; дублікати #99287, #99793, #100596; незлиті PR #98583, #100648). Unmatched URL рендеряться сервером, але без `experimental.globalNotFound` — стандартною англійською заглушкою поза `[lang]/layout`.
2. **500** на `/teams.rsc`, `/uk.rsc` (`InvariantError: Expected RSC response, got text/html … This is a bug in Next.js`, схоже — vercel/next.js#101449, закрито без виправлення) виникає лише за **поєднання proxy + динамічного `global-not-found`** (читав `headers()`); кожне окремо — 404 (замір рев'юера, варіанти B/C/D). **Правило:** коли proxy повернеться (фаза 7), `global-not-found` лишати статичним; e2e-перевірка `/teams.rsc` ловить цю регресію.
3. Proxy в Next 16 працює на Node runtime (`proxy.md`) і викликається на кожен запит сторінки.

**Рішення.**
- Мови — правилами `redirects` (`/en`, `/en/:path*` → 308 без префікса) і `rewrites.afterFiles` (решта, крім `/uk…`, `/en…`, `_next/`, → `/en/…`) у `next.config.ts`. За `rewrites.md` `afterFiles` виконуються після файлів, але до динамічних маршрутів. `src/proxy.ts` немає; з'явиться лише для логіки на запит (фаза 7, вузький matcher).
- `src/app/global-not-found.tsx` — **статичний** і двомовний: без JS видно обидві секції з власним `lang`; inline-скрипт до першого кадру ставить `html[lang]` за адресою (`/uk…` → `uk`) і ховає іншу секцію. Заголовок вкладки нейтральний — «404 · Slipstream»: React під час гідратації повертає текст `<title>`, тож мовний заголовок скриптом не втримати (перевірено трасуванням).
- Неіснуючі параметри закривати через `dynamicParams = false` + `generateStaticParams` (unmatched → серверний 404). Явний `notFound()` — лише коли інакше не можна; для нього `src/app/[lang]/not-found.tsx` (мова після гідратації через `next/root-params`).
- Catch-all `[...rest]` не використовуємо: він перетворює unmatched URL на `notFound()` і повертає баг 1.
- e2e перевіряє сирий серверний HTML 404, RSC-запити (404, не 500) і редирект `/en//evil.com` (лише свій домен) — проганяти й проти прев'ю Vercel (Task 8), бо нормалізацію `//` там не перевірено.
- `/_global-error` (службова сторінка Next, за прямою адресою відповідала 500 з кешем на рік) → `beforeFiles` rewrite на `/_not-found` (404); справжні помилки й далі 500.
- Регістр: редиректи `/EN…` нечутливі до регістру (308), `/UK…` → 404 — безпечно, лишаємо.
- Латентний ризик (Task 6): мова 404 живе в атрибутах `<html>`, які ставить скрипт; помилка гідратації client-компонента в 404 перемалює корінь і скине вибір (замір рев'юера з навмисним mismatch). Перевірити обгортку `<Suspense>` замірами, коли в 404 з'являться шапка/футер; `expectBrowser404` таку регресію ловить.
- `public/e2e-probe.txt` — перевірка, що rewrite не ламає `public/`; замінити на реальний файл, коли з'являться фото (фаза 3).

## 2026-11-11 · Токени, шрифти, тема (Task 4)
- **Кирилиця:** у `next/font` (16.4.5, `font-data.json`) Rubik Mono One має `cyrillic`, `latin`, `latin-ext`; IBM Plex Sans/Mono — теж. Усі три — з `subsets: ['latin','cyrillic']`. Plex Sans — змінний (один файл на 400–700). Plex Mono (500, 600) — `preload: false`: підписи нижче першого екрана. Замір: 4 preload-файли (display + body × 2 набори); переглянути за Lighthouse (Task 8).
- **Контраст (замір, WCAG 2.2):** жовтий фокус на світлому папері — 1.45:1 (< 3:1, SC 1.4.11) → токен `--focus`: `ink` у світлій темі, `yellow` у темній (і в шапці — Task 5). `--red` на папері — 4.13:1 → для тексту новий `--red-text` (`#C2261A` 5.30:1 / темна `#FF6B5A` 6.69:1); `--red` — лише плашки й графіка.
- **Перемикач теми:** `useSyncExternalStore` (джерело — атрибут `data-theme` + `prefers-color-scheme`), серверний знімок `null` → без розбіжностей гідратації; inline-скрипт збирається з тих самих констант (`themeScriptSource`) і покритий unit-тестом через `new Function`.
- **`src/app/icon.svg`** зроблено вже тут (у плані — Task 6): без іконки браузер запитує `/favicon.ico` → 404 у консолі, а smoke-тест вимагає 0 помилок консолі. Роундел — вихід `logo_gen.py`, побайтово збігається з опублікованим макетом головної.

## 2026-11-11 · Правки рев'ю Task 4
- **Цикл CSS-змінних (замір рев'юера, підтверджено тестом):** `@theme` Tailwind пише `--font-mono: var(--f-mono)`, а `--f-mono` посилався на `--font-mono` від next/font → поза елементом з класом next/font (404) усі шрифти ставали invalid. Змінні next/font тепер `--nf-*`; `--f-*` мають фолбек усередині `var()`. 404 отримав `fontVariables` і `ThemeScript` (збережена тема).
- **Перемикач теми без розбіжності з сервером:** обидві іконки й підписи в розмітці, видимий стан обирає CSS за `data-theme`/`prefers-color-scheme`; `useSyncExternalStore` прибрано. Без JS кнопка прихована (`html[data-js]` ставить ThemeScript). Ціль ≥ 30 px. Вибір в іншій вкладці застосовується (подія `storage`).
- **Фокус на темних поверхнях:** `.site-head`, `.mnav`, `.site-foot`, `[data-surface=dark]` → `--focus: yellow` (ink на `#16181D` дав би 1:1).
- **Моно** (`.font-mono`, `code` тощо) — `word-spacing: normal` навіть усередині `.display`.
- **`@theme inline`** доповнено (`grid`, `card`, `on-card*`, `on-color`, `focus`, `t-*`, `font-sans` → Plex).
- Темний `--blue: #2F55F0` — з `home_mockup` (в інших макетах темний `--blue` не перевизначено).
- **Ризики на потім (гіпотези, міряти в фазі 3 / Task 8):** фолбек-метрики next/font пораховані за латиницею — кириличний заголовок `.display` на фолбеку на рядок вищий (замір рев'юера: CLS 0.016 на один заголовок; бюджет < 0.1 тримається). Кириличні preload-и вантажаться й на EN-сторінках (~29 КБ).
- **Для Task 6 (розрахунок рев'юера):** білий текст на кольорах розділів не проходить AA — `#FF8000` 2.52, `#27D9C2` 1.78, `#1E8A63` 4.31; на помаранчевому й бірюзовому — текст `ink` (7.05 / 9.97).

## 2026-11-11 · Шапка, мобільне меню, футер (Task 5)
- **Активний розділ і перемикач мови — з `useSelectedLayoutSegments()`**, не з `usePathname()`: за rewrites `usePathname` на статичних сторінках дає розбіжність гідратації (docs `use-pathname.md`, «Avoid hydration mismatch with rewrites»). Query (`?q=…`) додається через `useSearchParams` у `Suspense`: сервер віддає посилання без нього, після гідратації — з ним.
- **Мова — посиланнями** з `hreflang` (працюють без JS, корисні для SEO), поточна — `<span aria-current>`; порядок UK | EN як у макеті; доступна назва «UK — Українська» (WCAG 2.5.3, знайдено axe).
- **Мобільне меню:** панель з `hidden`, під нею `inert` на `main` і футері, `Escape` повертає фокус, назва кнопки стала («Menu») — стан дає `aria-expanded`. Без JS бургер прихований, у шапці — посилання «Menu ↓» на розділи у футері (`#sections`).
- **Поріг бургера 1140 px** (у макеті 860): на 861–1135 px пункти меню переносились і виходили за край (замір критики impeccable; e2e на 861–1440 px). ≤ 359 px — стиснена шапка (на 320 px без цього +16 px скролу).
- **Заготовки 9 розділів** (лише `h1`) — уже тут, а не в Task 6: посилання меню інакше вели на 404 (помилки prefetch у консолі). Перший екран, метадані — Task 6.
- Стрілка `→` у мобільному меню — системним моно: у латинському наборі Plex немає U+2192, і її малював Arial (замір CDP).
- Футер: притиснутий до низу, посилання в тексті підкреслені (WCAG 1.4.1), розділи колонками в порядку меню; джерела фото/Wikipedia/Autosport повернуться разом з контентом (вимога ліцензій CC BY-SA).
- **Відкриті питання дизайну (до користувача):** жовтий означає водночас поточний розділ, hover і акцент «Гра» (успадковано з макетів); код «UK» чи «UA»; ліврейна смуга над футером.
