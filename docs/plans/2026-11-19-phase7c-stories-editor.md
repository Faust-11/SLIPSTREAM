## Що будуємо

### 1. Список `/admin/stories`
Таблиця (як у макеті): заголовок і адреса · стан (опубліковано/чернетка) · полоска тверджень ≥2 · одне · спірні · джерел ·
здоров'я посилань · стан перекладу EN. Дані — з файлів історій (завантажені разом зі збіркою) + перевірки; для
редагування база — завжди `main` з GitHub (`readMain`, sha фіксується — правка не відкотить чужу, патерн 7b).

### 2. Редактор `/admin/stories/<slug>`
Вкладки: **Тексти** · **Твердження** · **Джерела** · **Фото й адреса** · **Версії**.
- **Тексти.** uk/en: заголовок, лід, kicker; тіло — Markdown по розділах `##` (textarea на розділ, без WYSIWYG: формат
  має спец-розмітку `[^cN]`, `:::tldr`, `:::timeline`, `[[media:…]]`). Вставка виноски — вибором твердження зі списку.
- **Твердження.** Таблиця id · текст · статус (`ok/one/dis`) · джерела (чипи). Для `dis` — обов'язково `note`, `label`,
  `reader` (uk+en). Статус **підказується** з кількості незалежних видавців (правило README, 8) — як у `check_stories.py`.
- **Джерела.** id, назва, видавець, дата, URL, `kind` (primary/secondary), `lang`, автор. Вікіпедія — заборонено
  (правило 2). Показ «джерело без жодного твердження» і «твердження без виноски в тексті».
- **Фото й адреса.** Hero — через конвеєр 7b (Commons + власне, ліцензії за правилами 7b). Адреса (slug) — див. §5.
- **Версії.** Історія змін цієї історії — PR з міткою `admin`, що чіпали її файли; «Відкотити» — наявний `revertPublished`.
  Порівняння версій — diff із GitHub (поле `patch` файлів PR), без власного diff-рушія.

### 3. Валідація перед збереженням
TypeScript-версія правил `check_stories.py` (виноски ↔ твердження, статус ↔ кількість видавців, `dis` ⇒ note/label/reader,
однакові виноски й блоки в uk/en, формат `##`, заборона `[текст](url)` і списків поза `:::`, `race` рік/етап, `media`/`blocks`
існують). Python-скрипт лишається сторожем у CI (єдине джерело істини для змін поза адмінкою); щоб правила не розійшлись —
**тест-паритет**: TS-валідатор і `check_stories.py` на всіх 33 історіях + на навмисно зіпсованих копіях дають однакові
помилки. Є помилки → PR не створюється (чернетку зберегти можна з помилками — за рішенням користувача, питання 3).

### 4. Застарілий переклад
Нове поле в `story.json`: `translated` — **хеші оригіналу на момент перекладу** (заголовок, лід, kicker, кожен розділ `##`
за порядком). uk змінився → хеш не збігається → EN «застарілий» (чип у списку й у редакторі, поле/розділ підсвічені).
Кнопка «Переклад актуальний» оновлює хеші. Усі 33 наявні історії стартують як «актуальний» (хеші дописуються одним
PR-міграцією; перевірка — що uk/en виносок збігаються). Гіпотеза-альтернатива (відкинута): порівнювати дати комітів
uk.md/en.md — будь-яка поправка коми в uk зробила б EN «застарілим».

### 5. Адреса з редиректом
Перейменування slug = у одному PR: тека історії, `slug` у JSON, шляхи й `srcSet` фото (`public/img/stories/<slug>/…` —
перейменування `.webp`), посилання `links.stories` в інших історіях (37 перехресних посилань), запис
`{from → to}` у `src/data/curated/story-redirects.json`. Одноразова кодова зміна: `next.config.ts` читає цей файл у
`redirects()` (permanent). Перед дією адмінка показує, що ще посилається на адресу: інші історії, **код** (головна,
`og-images.json`) — для історій, прописаних у коді, перейменування блокується з поясненням («спершу кодовий PR»).
Картка прев'ю посилань (og) для нової адреси — картка розділу, поки хтось не перезапустить `scripts/og/build.mjs`
(так само, як для будь-якої нової історії; 7b-граблі).

### 6. Здоров'я джерел
- **Перевірка посилань** — за натисканням: для історії (пачками по ~6–8 URL, послідовно, прогрес на сторінці) і «усі»
  (793 URL ≈ 8–13 хв за замірами вище). Класи: `працює` (2xx/3xx), `мертве` (404/410/DNS/TLS), `не вдалося перевірити`
  (429/403/таймаут — не тривога). Захист від SSRF: лише `https?://` з даних історій, без редиректів у приватні мережі,
  таймаут і ліміт тіла (патерн Commons 7b).
- **Web Archive:** на кожному джерелі — стан «є копія / немає» (Availability API) і кнопка «Зберегти в Web Archive»
  (Save Page Now → у `story.json` джерела пишеться `archive` з адресою копії). Що з посиланням `archive` робить публічна
  сторінка — питання 5.
- **Результати перевірок не зберігаємо в репозиторії** (були б коміти на кожну перевірку); живуть у відповіді сторінки.
  Автоматичної щотижневої перевірки немає — квоту Actions вичерпано до 1.12 (14.11), а Vercel Cron на Hobby — раз на добу (за документацією Vercel, не мірялось) і без
  сховища результатів. Лічильник «21 без архіву» в Огляді — рахується з `archive` у файлах, мережі не потребує.
