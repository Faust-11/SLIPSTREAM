# Slipstream · Фаза 3c «Пілоти» (список) — план реалізації

> **For agentic workers:** Implement this plan task-by-task, checking off each step; verify each task before moving on.

**Goal:** `/drivers` і `/uk/drivers` за макетом https://claude.ai/artifact/XKv1UqRbBU5Fey8yXqu66g: підсумки (пілотів, чемпіонів, переможців гонок), картки учасників поточного сезону (місце, номер, очки, портрет, колір команди), таблиця всіх пілотів (пошук, фільтри «сезон / чемпіони / переможці», десятиліття, перша літера, сортування колонок, сторінки по 25). Сторінка пілота — наступний крок (3d); до того імена в списку без посилань (правило «без мертвих посилань»).

**Рішення користувача 12.11:** спершу список; імена українською — Wikidata + транслітерація; портрети — 419 вільних з макета (з перевіркою ліцензії на Commons) + пошук відсутніх (Wikidata P18 → Commons), решта — ініціали, нові фото згодом в адмінці (кураторське поле, як `hero` у командах).

**Architecture:** SQL — матеріалізоване подання `f1.driver_index` (міграція 0007) за правилами команд: старти — лише зі стартом (`f1.result_started`), перемоги, подіуми (за машинами), поули (`grid = 1`), титули (вирішені), роки, основна команда (найбільше стартів), поточний сезон (місце, очки, команда, номер). Збірка — один посторінковий запит. Таблиця — клієнтський компонент; без JS — повний перелік у `<noscript>`.

**Global Constraints:** як у 3a/3b (бюджети Lighthouse, axe, CSP, без логотипів, атрибуція фото лише внизу, числа лише з бази, розряди за мовою); повні перевірки — один раз, коли сторінка готова; `npm run build` чистить кеш відповідей бази; злиття — Rebase and merge за згодою; автор — Faust-11.
