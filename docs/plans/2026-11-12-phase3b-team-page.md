# Slipstream · Фаза 3b «Сторінка команди» — план реалізації

> **For agentic workers:** Implement this plan task-by-task, checking off each step; verify each task before moving on. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** сторінка кожної з 165 команд — `/teams/<id>` і `/uk/teams/<id>` (330 статичних сторінок) за затвердженим макетом McLaren; картки в списку `/teams` стають посиланнями на неї.

**Architecture:** усі числа рахує SQL у схемі `f1` (нові матеріалізовані подання, оновлюються тим самим `f1.refresh_derived()` і публікуються `check_live.py --publish`). Збірка робить **по одному запиту на подання на весь сайт** (не 330 × N): рядки групуються за командою в `src/lib/data/team-page.ts`. Наш контент (кольори, фото, назви, країни, засновник/база/Instagram) — у `src/data/curated/`. Графік «Сезон за сезоном» — SVG на сервері; підказка — малий клієнтський компонент (без JS графік і таблиця повністю читаються).

**Tech Stack:** як у фазі 3a (Next 16.4.5, React 19.2, TS strict, Tailwind 4 + `site.css`, Vitest, Playwright + axe) + SQL (Postgres 17, CI `db.yml`).

**Spec:** макет «Команда: McLaren» https://claude.ai/artifact/Riwh3TKMDvcGnhfvFxk45W (опублікована версія — єдине джерело: локальна тека `~/Desktop/F1/data` видалена 12.11). Розділи макета: банер (фото, штамп «Кубок конструкторів ×N», назва, підсумок, Instagram) → факти (країна, засновник, база, дебют, пілоти й місце поточного сезону) → смуга підсумків (Гран-прі, перемоги, подіуми, поули, дублі, Кубки конструкторів, титули пілотів) → «Сезон за сезоном» (графік місць + висновки + таблиця всіх сезонів) → «Чемпіони світу з <команда>» → «N перемог» (за пілотами, за Гран-прі, перша / 100-та / остання, повний перелік) → «Пілоти <рік>» (порівняння пари) → футер з авторами фото.

## Global Constraints

- Усе з фаз 1 і 3a: бюджети Lighthouse (a11y/BP/SEO ≥ 95, performance ≥ 92, LCP < 2,5 с, CLS < 0.1, TBT < 400 мс), axe — 0 порушень у обох темах, CSP без змін, без логотипів F1/команд, фото — лише вільні ліцензії Commons з авторами у згорнутому переліку внизу.
- **Правила підрахунку — як у 3a** (`f1.result_started`): Гран-прі — лише зі стартом; перемоги — за гонками, не за заявками; Кубок поточного сезону — лише коли математично вирішено. Кубки конструкторів — з 1958 (раніше заліку не було): графік і таблиця місць починаються з першого сезону команди в заліку; сезони до 1958 — у таблиці без місця.
- Виключення з заліку (`team_standings.is_eligible = false`, напр. McLaren 2007) — позначка «виключена з заліку» на графіку й у таблиці, без пояснювального тексту (редакційні тексти — фаза 5).
- Титули пілотів: чемпіон сезону, який у тому сезоні виступав за команду; якщо за кілька — зараховується команді, за яку проїхав більше гонок (правило в `docs/decisions.md`, тест на відомих випадках).
- Числа на сторінці — лише з бази/кураторських даних; жодних чисел у коді чи словниках. Розряди — за мовою (`1 017` / `1,017`).
- Посилання лише на існуючі сторінки: на пілотів, сезони, гонки й траси посилань поки немає (з'являться з їхніми сторінками); у списку `/teams` картки стають посиланнями (повертаємо правило, тимчасово зняте в 3a).
- Неіснуючий id → 404 (`dynamicParams = false`).
- Повні перевірки (e2e, незалежний рев'юер, `/code-review high`, Lighthouse, UX-прохід скриншотами 320–1440 px у двох темах) — **один раз, коли сторінка готова** (рішення користувача 11.11); під час розробки — unit, lint, typecheck, `db.yml` для SQL.
- Гілка `phase3/team-page` від `main`; у `main` — лише через PR із зеленим CI, Rebase and merge за згодою користувача; автор комітів — Faust-11.

## Рішення користувача (12.11)

1. **Банер:** фото є (127 команд) — широке фото з тих самих файлів Commons, що в картках; немає — банер кольору команди з назвою. **Недостатні фото потім додаються в адмінці** (фаза 7): фото банера — окреме кураторське поле `hero` (файл + автор + ліцензія + сторінка Commons), сторінка показує його, якщо воно є; адмінка лише заповнює це поле (контент у репозиторії).
2. **Засновник, база, Instagram — для всіх 165 команд.** Джерело — Wikidata (засновник P112, штаб-квартира P159, Instagram P2003) через SPARQL, звірка з англійською Вікіпедією; кожне значення з посиланням на джерело в `src/data/curated/team-facts.json`. Немає даних (у багатьох історичних немає Instagram) — рядок не показується. Розбіжності джерел — до користувача, не вгадувати.
3. **Висновки біля графіка:** автоматичні з даних (найдовша серія Кубків, найбільше перемог за сезон, найдовша перерва між Кубками, виключення) **плюс редакційні тексти вручну** — короткі пояснення до незвичних сезонів (виключення, дискваліфікації, перейменування, смерть пілота тощо), UK + EN, кожне твердження з джерелом (≥ 2 незалежні або позначка «одне джерело»), як у рушії історій. Обсяг першого проходу — команди з такими сезонами в даних (список рахує SQL) + 11 команд 2026; решта — дописуються пізніше (адмінка, фаза 7).
4. **Сторінки для всіх 165 команд**; у малих команд порожні блоки ховаються.

## Review Focus

1. Числа сходяться з незалежними джерелами на еталонних командах (McLaren, Ferrari, Brabham, Lotus / Lotus Racing, Andrea Moda): Гран-прі, перемоги, подіуми, поули, дублі, Кубки, титули пілотів — тест `db.yml`.
2. Межові команди: без фото, без Кубків, без перемог, лише сезони до 1958, команда поточного сезону без очок — сторінка без порожніх блоків і нулів-заглушок.
3. Збірка 330 сторінок: кількість запитів до бази не росте з кількістю сторінок (≤ 10 на збірку); час збірки — замір до/після.
4. Графік: клавіатура і екранний читач отримують ті самі дані (таблиця), підказка не перекриває точку, 320 px — горизонтальна прокрутка лише всередині графіка.
5. Розмір HTML сторінки Ferrari (найбільша: ~1 143 Гран-прі, 250 перемог) — бюджет ≤ 150 КБ gzip; повний перелік перемог — у `<details>`.
