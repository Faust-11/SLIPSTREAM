# Slipstream · Фаза 3d «Сторінка пілота» — план реалізації

> **For agentic workers:** Implement this plan task-by-task, checking off each step; verify each task before moving on. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** сторінка кожного з 793 пілотів зі стартом — `/drivers/<slug>` і `/uk/drivers/<slug>` (1 586 статичних сторінок) за затвердженими макетами Норріса й Гамілтона; імена пілотів у списку `/drivers`, `/drivers/all` і на сторінках команд стають посиланнями на неї.

**Spec:** макети «Ландо Норріс» https://claude.ai/artifact/DBi3xt3zHuQVns7LbYncqM (одна команда, 14 перемог) і «Льюїс Гамілтон» https://claude.ai/artifact/V9MaBbCbRdWAAWT7i7mvxz (три команди, 106 перемог, фільтр перемог за командою). Розділи макета: хлібні крихти → банер (портрет 4:5 з номером, штамп «Чемпіон світу ×N: роки», ім'я з прізвищем кольором команди, Instagram, факти: країна, народився, команди, номер, дебют, поточний сезон) → смуга підсумків (старти, перемоги, подіуми, поули, найшвидші кола, очки, титули) → «Сезон за сезоном» (стовпчики очок з місцем, колір команди сезону; таблиця) → «Проти напарників» (гонки й кваліфікації «хто попереду» за періодами) → «N перемог» (перша / з найдальшого місця на старті / остання; за Гран-прі; повний перелік у `<details>` з фільтром за командою) → «Віхи» (дебют, перший подіум, поул, перемога, титули) → автори фото.

**Architecture:** як у 3b. Усі числа рахує SQL у схемі `f1` (міграція 0008, нові матеріалізовані подання в `f1.refresh_derived()`); збірка робить по одному посторінковому запиту на подання на весь сайт (`once` + групування за пілотом у `src/lib/data/driver-page.ts`), не 1 586 × N. Наш контент (імена, портрети, Instagram, дата смерті) — `src/data/curated/`. Графік — SVG на сервері; фільтр перемог за командою — малий клієнтський компонент (без JS видно всі перемоги).

**Tech Stack:** без змін (Next 16.4.5, React 19.2, TS strict, Tailwind 4 + CSS розділу, Vitest, Playwright + axe; SQL — Postgres 17, CI `db.yml`).

## Global Constraints

- Усе з фаз 1, 3a–3c: бюджети Lighthouse (a11y/BP/SEO ≥ 95, performance ≥ 92, LCP < 2,5 с, CLS < 0.1, TBT < 400 мс), axe — 0 порушень в обох темах, CSP без змін, без логотипів, фото — лише вільні ліцензії Commons з авторами внизу, числа — лише з бази/кураторських даних, розряди за мовою.
- Правила підрахунку — як у `f1.driver_index` (0007): старти — `f1.result_started`; перемоги й подіуми — за гонками; поули — `grid = 1`; титул поточного сезону — лише коли математично вирішено. Числа сторінки пілота мусять збігатися з рядком списку (тест для всіх 793).
- Посилання лише на існуючі сторінки: команди — так; сезони, гонки, траси — поки без посилань (у макеті вони є; з'являться з їхніми сторінками).
- Адреса: `slug = id.toLowerCase().replace(/_/g, "-")` (`max-verstappen`, `cannoc`, `scott-brown`); у базі 5 id з дефісом або великою літерою — замір 12.11: 793 id → 793 унікальні slug, конфліктів з `/drivers/all` і `/drivers/credits` немає (тест тримає обидва інваріанти). Невідомий slug → 404 (`dynamicParams = false`).
- Порожні блоки ховаються: 161 пілот має 1 старт, 369 — до 5 (замір за фікстурою); без перемог — немає розділу перемог, без напарника зі спільними гонками — немає «Проти напарників», без портрета — банер кольору команди з ініціалами.
- Під час розробки — unit, lint, typecheck, `db.yml` (чернетка PR одразу); повний пакет (e2e, незалежний рев'юер, `/code-review high`, UX-скриншоти 320–1440 у двох темах, Lighthouse) — один раз, коли сторінка готова. Пуш пакетами, коміти — Faust-11, у `main` — PR із зеленим CI, Rebase and merge за згодою.

## Рішення за прецедентами 3b/3c (без питань до користувача)

1. **Сторінки для всіх 793 пілотів** (як «для всіх 165 команд»). Ризик — час збірки 1 586 сторінок: замір до/після, бюджет — у Review Focus.
2. **Портрет банера** — той самий файл Commons, що й аватар 96 px (ліцензію вже перевірено в 3c), розміри 420/840 px WebP (`scripts/curated/driver_hero.py`); джерело вужче за 420 px — показуємо в натуральному розмірі; немає портрета (344 пілоти) — ініціали на кольорі команди. Окреме фото банера (як у макеті Гамілтона) — кураторське поле `hero`, заповнюється пізніше (адмінка).
3. **Instagram і дата смерті** — Wikidata (P2003, P570) через `wikipedia_en` з бази, кожне значення з джерелом у `src/data/curated/driver-facts.json` (як `team-facts.json`). Вік показуємо лише живим; померлим — роки життя. Немає дати народження чи Instagram — рядок не показується.
4. **Очки за кар'єру** — сума підсумкових очок чемпіонатів (зараховані; у таблиці сезонів ті самі числа): Прост 768,5, а не 798,5 набраних. Еталони в `test_data.py`.
5. **Колір** — колір команди з `teams.json`; у команд без кольору (не виступають) — нейтральний токен. Акцент сторінки — остання команда пілота.
6. **Віхи й «особлива» перемога** — лише з даних: дебют, перший подіум, перший поул, перша перемога, титули; серед перемог — перша, остання й перемога з найдальшого місця на старті (якщо старт ≥ P5 і вона не перша/остання).
7. **Номери машин** — з результатів гонок, стиснуті в періоди («1 у 2026, 4 у 2019–2025»); у 1950–1973 номери змінювались від гонки до гонки — рядок показуємо лише коли періодів ≤ 3.

## Рішення користувача (12.11)

1. **«Проти напарників»** — усі напарники, з якими пілот стартував за одну команду щонайменше в **5 спільних гонках**, за періодами; разові заміни не показуються.
2. **Найшвидші кола** — замір API Jolpica 12.11: дані є лише з 2004 року (1950, 1965, 1980, 1995, 2003 — 0 гонок з усіх; 2004 — 18 з 18; 2010 — 19 з 19). Плитка — лише в пілотів, чия кар'єра повністю з 2004 року (89 з 793 за фікстурою); в інших — 6 плиток замість 7.
3. Кваліфікації в «Проти напарників» (рішення виконавця, той самий принцип «без неповних чисел»): рядок кваліфікацій — лише коли для всіх спільних гонок пари є дані кваліфікаційних сесій (API: 1980 — 0 рядків, 1995 — є); інакше лише рядок гонок.
4. Нагадування з 3c (не блокує): 48 українських імен з позначкою «unsure» стануть заголовками сторінок — перевірка за користувачем.

## Review Focus

1. Еталони (Вікіпедія, дата звірки в тесті): Гамілтон, Норріс, Шумахер, Сенна, Прост, Фанхіо, Кларк — старти, перемоги, подіуми, поули, очки, титули, найшвидші кола (де дані повні); сезони Гамілтона 2007–2026 (місце й очки кожного).
2. Сума по сезонах = підсумки = рядок `driver_index` — для всіх 793.
3. Межові пілоти: 1 старт; без портрета; дві команди за сезон (таблиця показує обидві); спільна машина 1950-х; пілот поточного сезону без очок; чемпіон поточного сезону до математичного вирішення.
4. Напарники: «попереду» ≤ спільних гонок; симетрія (A проти B = дзеркало B проти A) — тест на всіх парах.
5. Збірка: ≤ 6 нових запитів до бази на збірку незалежно від кількості сторінок; час збірки й розмір `.next` — замір до/після; HTML сторінки Гамілтона ≤ 150 КБ gzip.
6. Посилання: кожне ім'я пілота на сторінках команд і в списку веде на існуючу сторінку (e2e обходить усі `href` сторінки McLaren, Ferrari і першої сторінки таблиці).
